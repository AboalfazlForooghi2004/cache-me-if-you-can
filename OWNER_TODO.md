## Experimental private build — do not deploy yet
The repository now supports an **experimental** private build for staging only, not a production release. `PRIVATE_BUILD=1` requires `WORKER_SECRET` (at least 32 UTF-8 bytes, generate high entropy), `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `TRUSTED_CLIENT_IP_HEADER`, and `TRUSTED_PROXY_CONFIRMED=I_UNDERSTAND`. Supply these as temporary process environment variables, never paste them into a command log or commit. `node build.js` writes secret-bearing `private_dist/worker.js` and `private_dist/worker.lite.js`; never publish those files as static source or attach them to support tickets. Public files remain secret-free.

Do not enable until the owner verifies that the platform **overwrites** the configured client-IP header and cannot be bypassed; client-controlled forwarded headers make rate limits meaningless. Confirm Object Storage conditional PUT atomicity, listing order/consistency, fetch, CPU limits, and a retention/deletion policy for nonce/rate objects. No bucket or paid resource has been created. Check `/__diag` only on a protected staging deployment; it reports configuration, not proof of capabilities. LITE is a plausibility filter, not replay verification or proof of fair scores. The current browser does not yet submit online. Test on an actual phone and security-review moderation and score logic before release.
